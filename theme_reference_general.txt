CADRE THEME AUTHORING REFERENCE — CLEAN COMPONENT EDITION
========================================================
Includes OSC, Playlist (_pl), Titlebar (_tb), and Menu (_mn).
Derived from the supplied reference and component loaders. No implementation
source dumps or source appendices. Small authoring examples are allowed.
Static inspection only; not runtime-tested. Shared common loader not supplied.

HOW TO USE THIS DOCUMENT
------------------------
Use the authoring rules, OSC slot/decorations guide, and key entries below.
The added component catalogues contain a type, fallback/default, and purpose for
every scoped key looked up by the supplied playlist/titlebar/menu versions.
A suffix defines scope, not automatic support or automatic fallback behavior.
do not infer values. New component entries use actual loader fallbacks.
Shared fallback keys mentioned by a component are supported there even when
not separately enumerated in the original OSC-only GLOBAL / SHARED section.

PURPOSE
-------
This is the authoritative companion for an LLM creating or editing Cadre Player
theme files. A theme is always a simple Lua module:

    local M = {}

    -- theme settings

    return M

RULES FOR THE LLM
-----------------
1. Use only keys, button IDs, enum values, aliases, and fallback chains listed
   in this reference.
2. Never invent a key, button ID, enum value, alias, or fallback.
3. Preserve fallback order exactly.
4. Prefer global keys for app-wide changes.
5. Use scoped keys only for area-specific overrides.
6. Colors are RGB hex strings without '#', e.g. "F28C1E".
7. Alpha values are two-digit hexadecimal opacity values.
8. Sizes, spacing, offsets, and radii are plain numbers, usually pixels.
9. For inherited booleans such as glass blur, nil inherits the global value.
10. The seekbar is an independent OSC component with its own placement state.
    It is not merely an OSC slot widget.

VALUE FORMATS
-------------
color   RGB hex string without '#', e.g. "F28C1E"
alpha   Two-digit hex opacity value, e.g. "00", "30", "A0", "FF"
number  Lua number
boolean true or false
string  Lua string
enum    One of the listed canonical values
table   Lua table

ALPHA CONVENTION
----------------
Theme alpha fields use opacity values. common.ass_alpha converts these
two-digit hex values to ASS transparency when drawing:

    "00" = fully transparent
    "30" = low opacity
    "80" = half opacity
    "A0" = high opacity
    "FF" = fully opaque

Higher values mean more opacity.

Valid examples:
    "00", "1C", "30", "40", "80", "A0", "E0", "FF"


SCOPE SUFFIXES
--------------
(none)  Global/shared
_osc    On-screen controller / OSC
_pl     Playlist
_tb     Titlebar
_mn     Menu

FALLBACK MODEL
--------------
    <key>_<scope> -> <global key> -> built-in default

Example:

    color_text_osc -> text_color -> "F8FAFC"

NAMING GRAMMAR
--------------
    <property>_<target>[_<subtarget>]_<scope>

This grammar helps readability. It does not define support: use only keys in
this reference.

OSC SLOT SYSTEM, BUTTON IDS, AND PLACEMENT PRECEDENCE
================================================================================

OSC SLOTS
---------
Base slot keys:
    osc_L1, osc_L2, osc_L3, osc_L4
    osc_C1, osc_C2, osc_C3
    osc_R1, osc_R2, osc_R3, osc_R4, osc_R5

The loader supports slots 1 through 32 for each side, so custom themes may also
use keys such as osc_L6, osc_C7, or osc_R12.

Example:

    M.osc_L1 = "time"
    M.osc_C1 = "play"
    M.osc_R1 = "volume_slider"

ANCHORED SLOTS
--------------
Anchored slots are independent of their base slot. The suffix controls the
anchor; it does not replace the base slot.

Anchor suffixes:
    _top          Anchor to the top of the window.
    _center       Anchor to the vertical center of the window.
    _bottom       Anchor to the bottom of the window.
    _top_osc      Anchor to the top of the OSC panel.
    _center_osc   Anchor to the vertical center of the OSC panel.
    _bottom_osc   Anchor to the bottom of the OSC panel.

Examples:

    M.osc_L1_top = "title"
    M.osc_L1 = "time"
    M.osc_C1_center = "play"
    M.osc_C2_center = "next"
    M.osc_C3_bottom_osc = "seekbar"

`osc_L1_top` and `osc_L1` are independent placements.

SPECIAL COMPONENT BEHAVIOR
--------------------------

Title:
    A slot containing "title" replaces floating-title placement.
    If no title slot is used, the floating title is controlled by:
        enabled_title_osc
        position_title_osc

Time:
    A slot containing "time" replaces standalone elapsed/duration labels.

Seekbar:
    A slot containing "seekbar" places the seekbar track in that slot row.
    If no seekbar slot is used, position_seekbar_osc places the standalone
    seekbar track.
    Configure only one seekbar location: either a seekbar slot or
    position_seekbar_osc, not both.

Seekbar visibility:
    enabled_seekbar_osc = false
    hides the seekbar, its slot, hitbox, and seek labels.

Speed:
    speed_down, speed_reset, speed_up are independent button to control video speed.
    speed_control is a single button that opens a dialog for speed control wheel design
    speed_control_wheel make the wheel a button on directly osc, it has general button theming also a special value for its width:
    "width_speed_control_wheel_osc" and default value is 180.


PLACEMENT PRECEDENCE
--------------------

Individual placement is the default.

Individual ordinary row offset:
    offset_row_main_osc
    -> offset_button_row_osc
    -> offset_button_row
    -> 0

Individual anchored row offset:
    offset_top_osc / offset_center_osc / offset_bottom_osc
    -> offset_button_row_osc
    -> offset_button_row
    -> 0

Structured placement uses osc_layout. Fields supplied there override matching
individual placement settings, and automatic row movement is disabled.

Do not combine individual and structured placement unless structured fields
are intended to take precedence.

STRUCTURED LAYOUT
-----------------

osc_layout is an optional table.

Example:

    M.osc_layout = {
        button_row = {
            anchor = "top",
            offset = 14,
        },
        seekbar = {
            anchor = "below_buttons",
            gap = 8,
        },
    }

button_row fields:
    anchor  "top", "center", or "bottom"
    offset  number

seekbar fields:
    anchor       "above_buttons", "below_buttons", "panel_top", or "panel_bottom"
    gap          number; used with above_buttons/below_buttons
    panel_inset  number; used with panel_top/panel_bottom

Structured vertical layout disables automatic row movement that would normally
create clearance for the seekbar.

When osc_layout.seekbar.anchor is present, it overrides position_seekbar_osc.
When osc_layout.button_row.anchor or .offset is present, it overrides the
matching individual button-row settings.

OSC SLOT APPEARANCE OVERRIDES

osc_slot_overrides
    type: table
    purpose: Override the appearance of one exact OSC slot.

The table key must be the exact slot name, including any anchor suffix.

Examples:
    osc_L2
    osc_C1_center
    osc_L1_top
    osc_C3_bottom_osc

If osc_slot_overrides is nil, it is treated as empty.
If it is not a table, it is ignored with a warning.
Unknown option names, invalid values, and valid-but-non-applicable values are
ignored with a warning.

VALIDATION RULES
--------------------------------------------------------------------------------

Positive number fields:
    icon_size
    font_size
    hover_scale

Non-negative number fields:
    spacing
    button_height
    button_padding
    button_radius
    button_border_width
    hover_border_width
    hover_radius
    separator_width
    separator_height
    separator_radius
    icon_outline_width
    icon_outline_blur
    icon_shadow_blur

Finite number fields:
    icon_shadow_x
    icon_shadow_y

Color fields must be 6-digit RGB hex strings, e.g. "F28C1E".

Alpha fields must be two-digit hex opacity values.
    "00" = fully transparent
    "FF" = fully opaque

Boolean fields:
    icon_outline
    icon_shadow
    button_background
    button_border
    hover_border

button_gradient_type values:
    "left_to_right"
    "top_to_bottom"
    "circular"

button_border_sides must be a table whose keys are only:
    top, right, bottom, left

Each value must be boolean. Omitting it draws all sides.
